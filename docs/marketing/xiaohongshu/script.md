# 小红书：视频 + 图文发布包

两种发法任选，也可以都发：

- **视频**（第 1–5 节）：约 55 秒竖屏，画面和字幕已经做好（`video.html`），**你只需要录自己的声音，再按需换上自己的真实录屏**。
- **图文 / 实况图**（第 6 节）：8 张卡片，图片在中间、文字在下面，每张可以是会动的实况图。

## 1. 怎么做出成片（约 30 分钟）

1. **渲染画面**（约 5 分钟，需要 Chrome 和 ffmpeg）：
   ```sh
   bash scripts/render-xiaohongshu-video.sh
   ```
   得到 `dist/xiaohongshu.mp4`：1080×1920、30 帧、没有声音。想先看某一秒长什么样：`bash scripts/render-xiaohongshu-video.sh still 12 25`，图在 `dist/xhs-stills/`。
2. **录口播**：照下面的口播稿，用手机「语音备忘录」或电脑的 QuickTime 录。安静的房间、嘴离麦克风一拳、念得比平时慢一点。可以一段一段录，方便重来。
3. **剪辑**（剪映 / 必剪 / iMovie 都行）：导入 `xiaohongshu.mp4` 和你的口播，把每一段口播对到下面表里的时间。口播比画面短一点没关系，比画面长就把那一段的口播删减几个字。字幕直接用剪映「识别字幕」。
4. **（推荐）换上真实录屏**：见第 3 节。
5. 加背景音乐：**只用剪映 / 小红书自带的可商用曲库**，不要用来路不明的歌（会被限流或下架）。音量压到口播的 1/4 左右。
6. 导出 1080P 竖屏，封面用 `dist/xhs-stills/` 里挑一张（建议开场那一帧）。

想改画面：编辑 `video.html`，每个场景的时长在 `data-dur`，文字就在页面里。在 Chrome 里打开可以预览：空格播放，← → 切换场景。

## 1b. 背景音乐和配音（备用：不出镜、不出声时）

> 合成配音听起来有距离感，**更推荐 1c 的真人出镜版**（你的脸 + 你的声音）。这一节留作备用。

画面可以直接加上**原创背景音乐**和**配音**，一条命令：

```sh
bash scripts/render-xiaohongshu-audio.sh            # 纯音乐版 + 两种配音版
bash scripts/render-xiaohongshu-audio.sh music      # 只要纯音乐版（很快）
```

得到（在 `dist/`）：

- `xiaohongshu-music.mp4`：纯音乐版，55.5 秒，没有人声。
- `xiaohongshu-voice-yunxi.mp4`（男声）、`xiaohongshu-voice-xiaoxiao.mp4`（女声）：配音版，约 74 秒。每个场景的长度会**跟着配音自动调整**，声音和画面不会错位；音乐在说话时自动压低。
- 同名的 `.srt` 字幕文件，以及 `dist/audio/` 里分开的音轨（`music.wav`、`yunxi/voice.wav`…），想在剪映里自己混也可以。

台词在 `narration.json`（每个场景一句，想改直接改），重新运行即可。

**配音是怎么来的**：用的是文字转语音（TTS）。我对比了四种，并用语音识别（Whisper）把每句话"听"回来，和原文比对：

| 声音 | 与原文吻合 | 说明 |
|---|---|---|
| 云端神经语音·男（Yunxi） | **98%** | 自然，默认 |
| 云端神经语音·女（Xiaoxiao） | 94% | 自然 |
| macOS 系统语音（Tingting） | 82% | 机械，英文名读不好 |
| 本地开源 MeloTTS | 62% | 离线可用，但这段文案里读错太多 |

> 云端语音通过 `edge-tts` 调用微软的在线语音服务，**只会把台词文字发过去**（和官网上的文案一样是公开的）。这不是微软的正式 API，商用条款请你自己确认。想完全离线可以用 `ENGINE=melo`（质量较低），或者用你自己的声音：

**用自己的声音（语音识别会帮你检查）**：把每个场景录成一个文件，命名 `01.wav … 09.wav`，放进 `dist/audio/mine/voice/`，然后

```sh
ENGINE=files bash scripts/render-xiaohongshu-audio.sh voice mine
```

场景长度同样会按你的录音调整，并且会用语音识别检查你有没有念漏念错（见 `dist/audio/mine/asr-report.txt`）。

**音乐**：是用代码合成的原创曲子（柔和的铺底、轻轻的拨弦、很轻的节拍），没有使用任何采样，所以没有版权问题；它会随画面变化：开场很轻，光集出场时变亮，介绍功能时平稳，结尾收束淡出。它是"够用的氛围音乐"，不是专业制作的成品。想要更丰富的声音，可以在剪映 / 小红书里挑一首自带的可商用曲子，把 `dist/audio/` 里的配音轨和字幕放上去。

## 1c. 真人出镜版（推荐）：你的脸和声音 + 手绘白板

你对着手机说话，工具帮你剪，并在你说到某个词的时候，在白板上**一笔一笔画出对应的图**（Excalidraw 手绘风，和 Excalidraw 用的是同一个手绘线条库 rough.js）。

**1. 录**：用 `docs/marketing/xiaohongshu/teleprompter.html`（Chrome 里打开，空格开始，↑↓ 调速度，M 镜像）当提词器。竖屏录，脸在画面上半部分，安静的房间，手机离嘴一臂远。中间有口误就停一下重说那句，工具会把长停顿剪掉。台词里有一句 `【…】` 是留给你自己的，只有你能说的那句话。

**2. 剪**：

```sh
.venv-audio/bin/python scripts/audio/build-talking-video.py 我的录像.mov
.venv-audio/bin/python scripts/audio/build-talking-video.py 我的录像.mov --plan-only   # 只看画面安排，几秒钟
```

在 `dist/talking/` 得到成片 `.mp4`、字幕 `.srt`、画面安排 `-cues.txt`，以及 `-preview/` 里几张版面截图（先看这几张，不用看完整个视频）。

- 开头约 3.5 秒和结尾约 4 秒，**你的脸占满整个画面**；说到某个话题时，白板出现在上半屏，你的脸移到下半屏。
- 字幕是语音识别（Whisper，全程在你的 Mac 上）出来的，难免有错字：改 `.srt`，再运行加 `--captions 改好的.srt`。
- 脸在画面里偏上还是偏下：`--face-y 0.3`（0 是最上，1 是最下），决定白板出现时下半屏裁到哪里。
- `--no-sketches` 只要脸 + 字幕；`--no-music` 去掉背景音乐；`--no-trim` 保留所有停顿。
- 一轮大约 10 分钟（大部分时间在逐帧画白板），之后改字幕重跑还是这个时间。

**3. 白板是怎么跟着你说话的**：故事一共 **15 页**白板，按讲故事的顺序：`phone`（Mimo 只有手机版）→ `sliders`（专业软件的一堆滑块）→ `idea`（想法）→ `origin`（ChatGPT 原型 → Claude Code 挑毛病）→ `audit`（实测的改进）→ `sentences`（一句人话，一次修改）→ `mistake`（AI 也会错：白桌子的拿铁）→ `auto`（自动）→ `presets`（预设和裁剪）→ `save`（存进「照片」）→ `inspire`（张小样和边调边学的由来）→ `learn`（像素 → 直方图、光圈、亮部）→ `name`（Lucet 光集）→ `honest`（现在的限制和不会做的事）→ `invite`（邀请）。**配长版口播稿（`teleprompter.html?v=long-zh`，约 5 分钟）刚好 15 页全出现**；55 秒短版会出现其中 9 页左右。

每个图形绑在一个“关键词”上（比如 `auto` 对应你说“自动”），工具在识别出的文字里找这些词，到那一秒就开始画。所以：**照提词器念就行，但想改词，要保留这些关键词**（词表在 `scripts/lib/sketch_pics.py` 的 `BOARDS`）。没听到的词，图会紧跟着上一个画出来，所以页面不会缺东西；整页都没提到，这一页就跳过。想改图，编辑 `sketches.html`（用 `?board=learn&play=1` 在 Chrome 里循环预览）。

> 5 分钟的成片要把 15 页全部逐帧画出来，渲染大约要 30–40 分钟（只在第一次；改字幕再跑也是这个时间）。先用 `--plan-only` 看安排，再放心跑。

**白板里放真实截图**：`auto`、`presets`、`save` 三页（以及 `presets` 页里的裁剪）会放 `docs/marketing/xiaohongshu/pics/` 下的图片：`auto`、`presets`、`crop`、`save`（`.jpg` 或 `.png`）。现在放的是光集的真实截图；想换成你自己的截图或照片，用同样的文件名放进去覆盖即可，删掉某个文件就会回到手绘小图。成片里加 `--no-pics` 则全部用手绘图。图片也会一起打包进 `.excalidraw` 文件。目前只支持图片，不支持视频片段。

**也可以在 excalidraw.com 里打开**：所有 15 页都在**一个文件**里：`docs/marketing/xiaohongshu/excalidraw/lucet-story.excalidraw`（按故事顺序排成 3 行、每行 5 页，每页一个带名字的框，如“1 phone”“2 sliders”）。打开 https://excalidraw.com ，把文件拖进页面（或菜单 → 打开）即可编辑、改字、加图。这是单向导出：在 excalidraw.com 里改的不会回到视频里的白板；视频里的图仍然来自 `sketches.html`。改了 `sketches.html` 后，运行 `python3 scripts/export-excalidraw.py` 重新导出。文字位置是估算的，个别地方需要手动挪一下。

> 工具已经用一段合成语音的"替身录像"跑通过一遍（只验证版面、字幕、白板对时），没有正式成片。你的真实录像还没有。

## 3. 换成你自己的真实录屏（让视频更可信）

截图加动效能讲清楚，但**真实的操作录屏更有说服力**。你想换哪一段，就录哪一段：

| 想换的场景 | 录什么 |
|---|---|
| 自动 | 打开一张偏灰的照片 → 按 A → 按 `\` 来回对比前后 |
| 预设 | 在预设缩略图上依次点几个，看画面变化 |
| 裁剪 | 切到「构图」→ 在画面上拖动裁剪框、拖角缩放 |
| 存进「照片」 | 导出 → 保存到「照片」→ 切到「照片」App 里看到结果 → 拿出 iPhone 看同步过去的照片 |

录屏方法：Mac 上按 ⇧⌘5 →「录制所选部分」，框住光集窗口，不要把桌面上无关的东西录进去。放大一点录，手机上才看得清。每段录 8–10 秒就够。

**两种用法**：

- **在剪映里叠**：把录屏放在对应场景的时间段，盖住截图（最简单）。
- **在 `video.html` 里换**：把录屏文件放到 `docs/marketing/xiaohongshu/clips/`，改 `video.html` 顶部 `FOOTAGE`，例如 `auto: "clips/auto.mov"`。再用上面的渲染命令。（渲染时视频素材可能不会逐帧精确，换了录屏建议直接在剪映里剪。）

另外，**你自己的 DJI 画面**（飞行、风景）放在开场前 1–2 秒，会比纯文字开头抓人得多。

## 6. 图文版 / 实况图版（没有视频也可以）

不想做视频，可以发一组**图文笔记**：8 张 3:4 的卡片，**图片在中间、文字在下面**，每一张还可以是**实况图（Live Photo）**，按住就会动 3 秒。画面和文字都在 `slides.html` 里，想改字直接改。

```sh
bash scripts/render-xiaohongshu-slides.sh            # 静态图 + 实况图，约 3 分钟
bash scripts/render-xiaohongshu-slides.sh stills     # 只要静态图（十几秒）
```

得到：

- `dist/xhs-slides/01.jpg … 07.jpg`：静态图，1080×1440，直接能发。
- `dist/xhs-slides/live/01.jpg + 01.mov …`：实况图。每张是一对文件（封面图 + 3 秒动态），**用的是光集自己的实况图代码生成，并通过了系统的配对检查**。

八张卡片：封面 → Mimo 只有手机版 → 点一下「自动」（前后对比） → 预设 → 裁剪 → 存进「照片」→ 做法（真实的提交记录，和 Claude Code 一起做）→ 结尾。

### 怎么把实况图发到小红书

实况图要从 **iPhone 的相册**里选，所以先让它们进到「照片」里：

1. 在 Mac 上打开「照片」App，把 `dist/xhs-slides/live/` 里的**所有文件**（.jpg 和 .mov 一起）拖进去，或用「文件 › 导入」。同名的一对会合成一张实况图。
2. 在「照片」里确认它们带有「实况」标记，按住能动。如果显示成一张静止图加一段单独的视频，说明没有配成功，改用静态图（`01.jpg…`）即可。
3. 送到 iPhone：开着 iCloud 照片就会自动同步；或者在 Mac「照片」里选中这几张，用隔空投送发给 iPhone（会保留实况）。
4. 小红书：发布 → 相册 → 按 1 到 8 的顺序选中。实况图会有「实况」标记，可以选择保留动态效果。

> 这一步（导入「照片」、同步到 iPhone、在小红书里保留动态）我**没有在你的设备上实测过**，请你先拿一张试发（可以设成仅自己可见）再整组发。
